# LoongArch Pipeline CPU V0.9 FPGA Integration Package

## 1. What this package adds

This package adds a board-oriented hardware integration layer without
modifying the existing V0.8 CPU datapath or the validated I-Cache RTL.

New files:

| File | Purpose |
|---|---|
| `rtl/fpga/imem_bram.v` | Synchronous instruction ROM intended for BRAM inference |
| `rtl/fpga/pipeline_cpu_fpga.v` | Hardware integration wrapper around the existing V0.8 datapath and I-Cache |
| `rtl/fpga/ego1_top.v` | EGO1 top module: clock, active-low reset and 16 LEDs |
| `rtl/fpga/ego1_v09_pins.xdc` | EGO1 physical pin assignments |
| `rtl/fpga/ego1_v09_clock.xdc` | Optional 100 MHz clock constraint |
| `rtl/fpga/fpga_demo.mem` | 29-word demonstration program |
| `tb/pipeline_cpu/tb_pipeline_cpu_v09_fpga_smoke.v` | Wrapper-level architectural regression |
| `scripts/v09/add_v09_fpga_sources.tcl` | Adds sources, constraints and testbench to the open Vivado project |

The integration wrapper reuses these existing modules:

- `pipeline_cpu_core_v08_mdu_datapath`
- `pc_if_controller`
- `pipeline_control_unit`
- `icache_if_adapter`
- `icache_2way_latency`
- `dmem_latency`
- The existing decoder, ALU, register file, forwarding, hazard and MDU modules

The simulation-only `pipeline_cpu_core_v08_mdu` wrapper and
`imem_latency` are not used by the new hardware top.

## 2. Important address and memory configuration

- CPU-visible reset PC: `0x00001000`
- I-Cache physical ROM address: `CPU_PC - 0x00001000`
- ROM capacity: 256 words / 1 KiB
- Program image: 29 words
- Program window: `0x00001000` through `0x00001070`
- Data memory: existing internal `dmem_latency`, 256 words
- Default hardware DMEM latency: 4 cycles for reads, 5 cycles for writes

`fpga_demo.mem` is based on the repository's V0.8 basic MDU program.
Its final `0xffffffff` invalid-instruction marker is replaced with
`0x02800000` (`ADDI.W r0,r0,0`), so the FPGA demo ends with a harmless NOP.
The program-window limit prevents the PC from issuing beyond the 29-word image.

The ROM defaults unused words to `ADDI.W r0,r0,0`. The I-Cache can therefore
refill the final four-word cache line without encountering uninitialized data.

## 3. EGO1 board mapping

The XDC targets the EGO1 board using the `XC7A35T-CSG324` device.

| Signal | EGO1 FPGA pin | Meaning |
|---|---:|---|
| `clk` | P17 | 100 MHz system clock |
| `sys_rst_n` | P15 | Dedicated active-low reset button |
| `led[0]`..`led[7]` | K3, M1, L1, K6, J5, H5, H6, K1 | D1_0..D1_7 |
| `led[8]`..`led[15]` | K2, J2, J3, H4, J4, G3, G4, F6 | D2_0..D2_7 |

All I/O standards are `LVCMOS33`.

LED meaning:

- `led[7:0]`: low byte of the latest architectural WB data
- `led[12:8]`: destination register of the latest architectural WB
- `led[13]`: program completed (sticky)
- `led[14]`: fetch / memory / unsupported-instruction fault (sticky)
- `led[15]`: heartbeat

The pin mapping follows the EGo1 User Manual V2.x. Verify the board revision
before programming hardware.

## 4. Install into the repository

1. Extract this ZIP into the repository root:
   `D:\CPU_Project\LoongArch-Pipeline-CPU`
2. Allow Windows to merge the `rtl`, `tb`, `scripts` and `docs` folders.
3. Do not overwrite or delete existing V0.8 files.
4. Open the existing project:
   `build\loongarch_cpu_v09_fpga\loongarch_cpu_v09_fpga.xpr`

## 5. Configure the existing Vivado 2019.1 project

In Vivado, open the Tcl Console and run (adjust the drive/path if needed):

```tcl
source D:/CPU_Project/LoongArch-Pipeline-CPU/scripts/v09/add_v09_fpga_sources.tcl
```

The script:

- Adds any missing existing RTL dependencies without replacing files.
- Adds the three new FPGA Verilog modules.
- Copies `fpga_demo.mem` beside the `.xpr` and uses its absolute path.
- Adds the EGO1 pin-constraint file.
- Preserves the existing `icache_timing.xdc`.
- Adds `ego1_v09_clock.xdc` only if no existing `create_clock` targets `clk`.
- Sets synthesis top to `ego1_top`.
- Sets simulation top to `tb_pipeline_cpu_v09_fpga_smoke`.

If the script reports a missing source file, stop and send the exact Tcl error.
Do not manually substitute a similarly named module.

## 6. Verification sequence

Perform these steps in order:

1. **Behavioral simulation**
   - Flow Navigator → Simulation → Run Simulation → Run Behavioral Simulation.
   - Expected final message:
     `ALL TESTS PASSED (V0.9 FPGA wrapper + BRAM I-Mem + I-Cache + V0.8 CPU)`
   - The regression checks 23 WB commits, 2 Store commits, one branch redirect,
     15 MDU starts/results and 4 data-memory request/response pairs.

2. **Synthesis**
   - Run Synthesis.
   - Confirm that `ego1_top` is the selected top.
   - Inspect whether `imem_bram.rom` is inferred as Block RAM.
   - Inspect warnings about `$readmemh`, missing memory files, latches or
     unresolved modules. Do not ignore such warnings.

3. **Implementation**
   - Run Implementation only after synthesis succeeds.
   - Review I/O and timing DRC messages. Every top-level port must be constrained.

4. **Bitstream**
   - Generate the bitstream only after simulation, synthesis and implementation
     are all successful.
   - Program the EGO1 board only after confirming the board revision and pins.

This package has been prepared from the repository RTL and board documentation,
but it has **not** been run in the user's local Vivado installation or on the
physical EGO1 board. The smoke test must be run locally before claiming PASS.

## 7. Scope and limitations

- This is the first FPGA integration milestone, not a claim of completed
  FPGA validation.
- The CPU still implements the existing V0.8 supported instruction subset.
- The data memory is internal FPGA memory; the EGO1 external SRAM is not used.
- Exception/trap handling is not added.
- The completion indicator waits for a 128-cycle quiet drain after the final
  in-range fetch. It is a board status indicator, not an architectural halt.
- If the program image changes, update `PROGRAM_WORDS` to the exact number of
  words and update the smoke-test expectations accordingly.

# CPU V0.4 · Branch Redirect / Flush 实际接口与验证范围

## 模块与代码版本
- CPU 顶层：`pipeline_cpu_core_v04`（`rtl_test_only/pipeline_cpu_core_v04.v`）
- 分支解析：`branch_resolve_v04`（EX 阶段、测试专用独立模块）
- 复用 V0.3 正式依赖：Decoder、ImmGen、ALU、RegFile、IF/ID、ID/EX、EX/MEM、MEM/WB、Forwarding、Load-use Hazard、DMEM。
- 不修改上述既有稳定 RTL。与正式 V0.9 PC/IF、I-Cache 及 `pipeline_control_unit.v` 的总线级协议集成尚未完成。

## 顶层端口
| 端口 | 方向 | 含义 |
|---|---|---|
| `clk`, `rst` | 输入 | 10ns 周期测试、同步高复位 |
| `if_valid`, `if_pc[31:0]`, `if_inst[31:0]` | 输入 | 流式指令提供者 |
| `if_ready` | 输出 | 上升沿 `if_valid && if_ready` 才接受 |
| `branch_resolve_valid` | 输出 | EX 阶段存在有效分支（包括不跳转的 BEQ/BNE） |
| `branch_redirect` | 输出 | EX 分支成立，将冲刷年轻指令 |
| `branch_redirect_pc[31:0]` | 输出 | 成立的跳转地址；未跳转时为 0 |
| `load_use_stall` | 输出 | 暂停外部 IF 并保持 IF/ID，向 ID/EX 插入 Bubble |
| `wb_commit_valid/pc/rd/data` | 输出 | 逐条寄存器写回的观察接口，r0 写入被屏蔽 |
| `mem_store_commit_valid/pc/addr/data` | 输出 | 同步 Store 写入观察接口 |
| `id_unsupported`, `id_raw_hazard` | 输出 | 译码过滤 / RAW 诊断信号 |

## 优先级与架构约定
1. 同步 Reset → Branch Redirect Flush → Load-use Bubble / IF Stall → 正常接受新指令。
2. **Redirect 不等于 Stall**：Load-use 的输入要重试；Redirect 的错误路径输入必须作废，下一周期改用新 PC。
3. Branch 只 Flush IF/ID 和 ID/EX；EX/MEM、MEM/WB 按既有指令向前推进。禁止错误路径 Store / WB 发生架构副作用。
4. BEQ/BNE 使用前递后的两个 EX 操作数；JIRL 目标使用 `rs1+offs16`，清零 bit0。
5. BL 固定写 r1；JIRL 目的寄存器来自 rd。两者数据均为该条指令 PC+4。
6. `WB_SEL=00` ALU、`01` DMEM、`10` PC+4。前递网络对 EX/MEM 的 PC+4 也视为 ready。
7. 此阶段不支持 Cache Miss、内存多周期反压、异常/中断、非对齐访存、真正完整的 Fetch PC Controller。

## 独立参考程序与检查
`branch_v04.mem`：62 个 ROM word，基址 `0x1000`。
- BEQ/BNE：正确/错误分支、前递依赖、Load-use 后比较。
- B：无条件正向跳转；BNE 向后循环跳转（负偏移）。
- BL/JIRL：PC+4 链接寄存器与 JIRL 目标地址。
- Redirect：错误路径 Store 和算术指令绝不提交。
- 逐笔比对 27 次 WB、6 次 Store、16 次分支决策（10 taken/6 not taken）。
- 3 次 Load-use 暂停，非法机器码 2 条被过滤（周期模型预计）。
- 采用独立 Python ISA 解释器生成固定期望表，同时用另一个周期模型复核；不是 RTL 行为仿真通过的证据。

## 后续与 V0.9 接轨注意
外部 IF producer 当前立即访问 ROM，没有 Cache 延迟。对接 V0.9 时需要根据 **请求接受/响应有效** 区分已发请求、尚未接受请求与需要丢弃的旧分支响应，不能直接照搬此测试专用 `if_ready` 到 I-Cache/Adapter，也不能用 Redirect 直接撤销已接受的请求。

# V0.5 — I-Cache + PC/IF 与五级流水线 CPU 的真实模块联合测试

## 设计范围

此包仅**新增** `pipeline_cpu_core_v05.v` 以及 Testbench，不更改任何 V0.1～V0.4、V0.9、I-Cache、Adapter、CPU27 的既有正式代码。测试顶层实例化正式的 `pc_if_controller`、`pipeline_control_unit`、`icache_if_adapter`、`icache_2way_latency`、`imem_latency` 和 V0.4 CPU。V0.9 自身是测试用模块，不在此重复实例化，以免 IF/ID 重复产生。

## 关键时序与协议

| 时刻 | 协议要求 |
|---|---|
| IF 请求 | PC/IF 保持请求地址，直到 Adapter `if_req_valid && if_req_ready` 上升沿接受 |
| Cache Miss | Adapter 单 outstanding 等待 Cache refill；IMEM 有固定可配置延迟 |
| IF 响应 | Cache Adapter 保留 `resp_pc/inst`，CPU 接收能力满足才 `resp_fire` |
| Load-use | 保持 V0.4 的 IF/ID Stall + ID/EX Bubble；响应留在 Adapter 中等待，EX/MEM 旧 Load 前进 |
| Branch Redirect | EX 阶段 redirect 同步广播到 PC/IF、Adapter 和 V0.4；旧响应无效化，旧 Cache Miss 继续被 Adapter drain；分支自身进入 EX/MEM |
| 指令地址 | CPU 可见 `0x1000 + 4*i`，IMEM 可见 `4*i`，仅转换于新增适配顶层，不改原始 Cache 地址判断 |
| 指令写回 | 使用正式 V0.4 的 WB/Store 提交信号逐笔断言，错误路径不能发生副作用 |

## 主要参数

- `PC_BASE = 32'h00001000`，虚拟程序起始 PC。
- `PROGRAM_WORDS = 62`，限制测试程序范围。**不代表完整处理器的异常或取指停止架构。**
- `IMEM_LATENCY = 3`，由现有正式 `imem_latency` 负责。
- `IMEM_FILE` 留空时，可由配套 Testbench 加载 `u_imem.rom`，避免在 Vivado 工程中修改正式源码。
- `if_delivery_allow` 专用于 Testbench 注入暂停，验证 Adapter 对完整响应的稳定保持；不是最终 SoC 的全局 MEM/WB 反压。

## 预期回归（均需以 Vivado 实际运行为准）

| 类别 | 预期 |
|---|---|
| WB | 27/27 次，逐笔比较 PC / rd / data |
| ST.W | 6/6 次，逐笔比较 PC / addr / data |
| Branch | 16/16 次，10 taken、6 not-taken |
| Unsupported | 2 |
| IF | 虚拟 PC 与 ROM 字一致，缓存响应匹配未完成请求 |
| Cache | Hit、Miss、4-word refill 均命中，响应阻塞/Redirect Drain 有覆盖 |
| 错误 | 0（预期，不是已取得的仿真结论） |

**与 V0.4 的区别：** 单 outstanding Cache 使 CPU 连续指令间出现 fetch bubbles，因此 Load-use Stall、EX/MEM Forwarding 的命中次数可能不同；这轮联合测试不能替代原有 V0.4 高频指令流的 880ns 回归结果。

## 验证边界

1. 本阶段只集成指令缓存，数据缓存以及多周期数据访存反压仍未纳入。
2. 现有 `icache_2way_latency` 对错误地址仅给出无效响应，尚无完整取指异常路径。
3. 测试 ROM 的字数是有界的，最后一字后暂停取指，以免执行未定义测试空间内容。
4. 不据此宣布 CPU27 指令全集、FPGA 时序与最终性能已经通过。

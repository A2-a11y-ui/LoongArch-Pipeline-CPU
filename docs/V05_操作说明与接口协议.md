## 1. 本版本的边界

- **分支**：`feature/icache-if-adapter`，由队员 B 负责。
- **新增文件**：`rtl/memory_cache/icache_if_adapter.v`、`tb/tb_icache_if_adapter.v`。
- **不可覆盖**：原有 `icache_2way_latency.v`、`imem_latency.v`、`cpu_top.v`、`decoder.v`、队员 A 的 `if_id_reg.v`。
- **实验状态**：本包源码经过接口检查和静态复核；不声称已经在 Vivado 中通过仿真。请在 Vivado 2019.1 运行 `tb_icache_if_adapter` 验证。
- **硬件限制**：原始 I-Cache 仅支持 1 KiB、字对齐地址；后备存储器为模拟固定 3 周期延迟的 ROM。当前设计不是完整流水线 CPU，也不是 FPGA 下载工程。

## 2. 实际连接架构

```
IF 控制（A） -> IF–Cache Adapter（B） -> 2-way LRU I-Cache（已验证）
                                          -> imem_latency（仿真存储器）
IF 控制（A） -> IF/ID Register（A）
```

Adapter **内部实例化**原始 `icache_2way_latency.v`；其 `mem_*` 端口连接外部存储器。不要在同一测试平台额外实例化第二个 Cache。

## 3. IF 接口契约（建议版 V0.5，待双方冻结）

| 信号 | 方向（以 Adapter 为准） | 规则 |
|---|---|---|
| `if_req_valid` | 输入 | IF 提供有效请求；需保持到 `if_req_ready` 握手 |
| `if_req_addr[31:0]` | 输入 | 与请求一起保持稳定；字节地址 |
| `if_req_ready` | 输出 | Adapter 空闲且无复位/Redirect 时可接受请求 |
| `if_resp_valid` | 输出 | 完成的响应存在且未被重定向取消 |
| `if_resp_ready` | 输入 | IF 允许在时钟上升沿消费响应；可用来施加反压 |
| `if_resp_pc[31:0]` | 输出 | 返回指令的原始请求 PC，**不可**用当前 PC 代替 |
| `if_resp_inst[31:0]` | 输出 | 返回指令；无效请求返回零 |
| `if_resp_error` | 输出 | 地址未对齐、超出目前模拟 ROM 的 1 KiB 范围等错误 |
| `redirect` | 输入 | 同步高电平脉冲；取消尚未消费的旧指令响应 |
| `busy` | 输出 | 有未完成请求或待消费响应；仅为状态指示 |

**请求接受**：`if_req_valid && if_req_ready` 在上升沿。

**响应消费**：`if_resp_valid && if_resp_ready` 在上升沿。

**重定向优先级**：`rst > redirect > response completion / consumption > new request`。

**十分重要**：这个 V0.5 `redirect` 输入**不**带 `redirect_pc`，也**不会自动发起新 PC 请求**。队员 A 的 IF 控制必须更新 PC，并在 `if_req_ready` 恢复后发出新取指请求。Redirect 不会修改原始 Cache 内容。

## 4. Cache Miss + Redirect 的处理

`icache_2way_latency.v` 必须一直看到相同的 `req_valid/req_addr`，直到 `ready=1`。它无法真正取消正在进行的回填。

Adapter 状态：

```
IDLE --请求握手--> WAIT --Cache响应--> RESP --IF消费--> IDLE
                       |                  |
                 Redirect              Redirect
                       v                  v
                     DRAIN --回填完成--> IDLE
```

- `ST_WAIT` 被 Redirect 打断，若旧 Cache 未 `ready`，进入 `ST_DRAIN`，持续保持旧请求直到 Cache 返回，旧结果不向 IF 发布。
- `ST_RESP` 被 Redirect 打断，清空已缓冲的旧结果；新请求只会在 `IDLE` 重新接受。
- 在 Cache 完成的**同一个时钟沿**发生 Redirect，直接丢弃旧响应并返回 `IDLE`。
- 连续 Redirect 可以继续保持失效状态；上层 IF 仅在允许握手时发送最新 PC。

**设计权衡**：排空旧 Miss 可能增加分支跳转响应时间，但能保留原始 Cache 的独立功能验证，不需要修改回填状态机。

## 6. 测试覆盖

1. 冷启动 Miss 与四字回填；
2. 同行 Hit、无额外后备存储访问；
3. `if_resp_ready=0` 时保持 PC/Inst/valid；
4. Miss 期间 Redirect → `DRAIN` → 只返回新 PC 指令；
5. 已缓冲响应期间 Redirect，旧响应丢弃；
6. 非法地址通过 `if_resp_error` 上报；
7. 未完成 Miss 期间 Reset；
8. Redirect 与发新请求同时出现，Redirect 优先；
9. Cache 即将完成时 Redirect，避免同周期旧结果泄漏。

**本包没有检验**：IF/ID 寄存器联合控制、整机 27 指令回归、Cache 接口全负载性能、跨时钟域、多个未完成请求或 FPGA 实现后时序。这些属于后续版本。

## 7. 交给队员 A 的最小接口说明

> B 已独立新增 IF–I-Cache Adapter，使用 `if_req_valid/if_req_ready` 接受 PC 请求，使用 `if_resp_valid/if_resp_ready` 返回指令及关联 PC。Cache Miss 和 Redirect 同时发生时会排空旧请求但不发布错误路径响应。上层 IF 负责在 Redirect 后发送新的目标 PC，IF/ID 的 Flush/Stall 优先级仍由 A 维护。目前接口是建议版，整机接入前需双方冻结。注意不能把 Adapter 的 `busy` 直接等价连接到 `if_id_reg.stall`。
